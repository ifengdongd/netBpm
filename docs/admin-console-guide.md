> 地址：`http://localhost:5081/`　｜　适用版本：v1.29 之后（`src/` 主干）　｜　更新：2026-11

> 相关文档：`docs/process-design-guide.md`（建模规则）、`docs/approver-resolution-guide.md`（审批人从哪来）、`docs/leave-external-task-setup.md`（外部任务端到端示例）。

## 0. 五分钟上手

### 0.1 启动控制台

```bash
# 后端（同时托管控制台前端与设计器）
dotnet run --project src/NetBpm.Admin
# 浏览器打开 http://localhost:5081/ ，未登录会跳到 /login
```

数据库连接取 `src/NetBpm.Admin/appsettings.Development.json`（默认 `MySql` + `netbpm_admin` 库，`AutoMigrate: true` 会自动建表）。
控制台前端由该宿主托管（`wwwroot`），改过 `web/admin` 前端源码后需要 `npm run build` 才会生效；开发期可用 `npm run dev`（默认代理到 5081，可用 `NETBPM_API_TARGET` 改目标）。

### 0.2 建一个管理员账号

控制台**没有注册入口**，账号只能用命令行创建：

```bash
dotnet run --project tools/NetBpm.DbMigrate -- users add \
  --username admin --display-name 管理员 --scopes netbpm.admin \
  --provider mysql --connection "Server=127.0.0.1;Database=netbpm_admin;User ID=root;Password=;"
```

- 口令至少 8 位；不给 `--password` 会交互式输入（不回显）。
- `--scopes netbpm.admin` 是**超级范围**，同时覆盖旧管理面（`netbpm.admin.*`）与平台面（`workflow:*`）——详见 §14。
- 账号已存在时命令会提示改用 `reset-password`。

### 0.3 最短的一条成功路径

| 步骤 | 去哪 | 做什么 |
| --- | --- | --- |
| 1 | 流程模型 `/models` | 「导入模型」选一个 `.bpmn20.xml` |
| 2 | 同一行 | 点「部署」，确认弹窗 → `已部署：xxx v1` |
| 3 | 部署管理 `/deployments` | 展开该部署 → 行内「发起」 → 填变量 → 「发起」 |
| 4 | 实例监控 `/monitoring` | 「待办任务」页签 → 行内「完成」 |
| 5 | 实例监控 | 「运行实例」→「详情」→ 看流程图与时间线 |

## 1. 登录与界面

### 1.1 登录页（`/login`）

页面标题 `NetBpm 控制台`，副标题 `登录以访问流程管理`。顶部三个切换：**账号密码 / API Key / Bearer Token**。

**① 账号密码**（推荐日常使用）

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 登录名 | 是 | 占位提示 `如 admin` |
| 口令 | 是 | —— |
| 租户（可选） | 否 | 占位提示 `账号绑定了租户时必填` |
| 保持登录 | 勾选 | `保持登录（跨标签页共享，设计器也可直接读取）` |

走 `POST /api/auth/login`，成功返回 JWT，直接当 Bearer 用。

**② API Key**：填服务密钥，可选填 `操作人（X-User-Id，可选）`、`租户（X-Tenant-Id，可选）`。
**③ Bearer Token**：直接粘一个现成的 JWT。

两种凭据模式都会先打 `/api/auth/me` 校验，失败提示 `凭据校验失败：后端返回 401（密钥无效，或未配置鉴权但后端不可达）。`

**常见登录失败**

| 提示 | 原因 |
| --- | --- |
| `jwt_not_configured` | 服务端没配 `NetBpm:Security:Jwt:SigningKey`，账号密码登录不可用；改用服务凭据 |
| `account_locked` | 连续失败达上限（5 次）临时锁定 |
| `tenant_mismatch` | 账号绑定的租户与提交的租户不一致 |
| `登录尝试过于频繁，请稍后再试` | 按 IP 限流（HTTP 429） |

> ⚠️ 未勾选「保持登录」时，凭据只存在**当前标签页**（`sessionStorage`），顶栏会出现橙色标签 `仅本标签页`，关掉浏览器就要重登。
> 勾选时写 `localStorage`（键 `netbpm.admin.credential.v1`），**流程设计器读的是同一个键**，所以进设计器不用再登一次。

### 1.2 顶栏

左侧是当前菜单名，右侧是身份区：

- **身份标签**：金色盾牌图标 = 拥有 `netbpm.admin`（超级管理）；蓝色 = 普通身份。鼠标悬停显示鉴权方式 / 登录名 / 租户 / 授权范围 / 有效期。
- **租户标签**：身份绑定了租户时才出现。
- **`退出`**：清除凭据回登录页。

凭据过期会**先本地判断**再跳登录，提示 `登录已过期，请重新登录`；服务端返回 401 时提示 `登录已失效，请重新登录`。

### 1.3 两条必须认识的横幅

控制台顶部可能弹出两种告警，它们只和**部署形态**有关，不是功能故障：

| 横幅 | 文案 | 怎么处理 |
| --- | --- | --- |
| 红色（指错宿主） | `当前后端不是 Admin 宿主（缺少 /api/admin 端点），请把控制台指向 NetBpm.Admin（默认 5081）` | 管理端点 `/api/admin/**` 只在 `NetBpm.Admin` 提供；`NetBpm.Rest`（5080）只有 designer / runtime / identity |
| 黄色（宿主过旧） | `Admin 宿主是旧构建：缺少 /api/admin/jobs 等新端点，请重新编译并重启 NetBpm.Admin` | 前端 rebuild 了但后端还是老进程，重启即可 |

自检靠两个探针：`/api/admin/models?maxResults=1` 判宿主，`/api/admin/jobs/stats` 判新旧。

### 1.4 菜单地图

## 2. 流程模型（`/models`）

这是整个控制台的起点：**BPMN 在这里编辑与部署**。

### 2.1 列表

工具栏左侧：搜索框 `搜索名称 / 流程 Key / 描述`（回车或点搜索才生效，清空即撤销）+ 计数 `共 N 个模型` / `匹配 N 个模型`。
右侧按钮：`刷新`、`导入模型`、`新建模型`。

表格四列 + 操作：`流程名称`、`流程 Key`（Tag）、`发布状态`、`最近修改`。

**发布状态**三种组合：

| 显示 | 含义 |
| --- | --- |
| `未发布` | 从没部署过，或模型是新建的空壳 |
| `线上 v3` + `未发布修改`（橙） | 模型改过但没重新部署 |
| `线上 v3` + `已同步`（蓝） | 内容已与线上版本一致 |

悬停 `线上 vN` 会显示 `部署于 2026/11/3 10:00:00`。

### 2.2 导入模型

点「导入模型」→ 选 `.bpmn` / `.xml`（同一文件可连续导入）→ 前端读文本、调 `POST /api/admin/models/import`。

- **process key 与名称由后端从 XML 推导**，文件名（去掉扩展名）只作为名称兜底。
- 成功：`已导入模型：leave_days_approval`；失败：`导入失败：<原因>`。
- 导入成功后 XMl 里的 `process id` 就是流程 Key，**后续所有地方都靠它对齐**（部署、发起、字典、表单 schema）。

### 2.3 新建 / 编辑（内嵌设计器）

「新建模型」→ `/models/editor?action=new`；行内「编辑」→ `/models/editor?modelId=xxx`。

页面顶部一条栏：`返回列表` + 说明文字（`新建流程模型（下方为内嵌设计器）` 或 `编辑流程模型（下方为内嵌设计器）`），下方是 iframe 加载的**设计器**（`/designer/index.html?...&embed=1`，`embed=1` 会隐藏设计器自带的菜单）。

设计器里能做的事：
- 拖拽画 BPMN（调色板含开始 / 结束 / 用户任务 / 服务任务 / 排他网关 / 并行网关 / 定时边界 等）；
- 右侧属性面板改 `办理人（审批人）`、`候选用户`、`候选组`、`表单属性`、`服务任务 → 主题（外部任务）`、条件表达式；
- 顶部工具栏保存（写回模型）、校验。

> ⚠️ **保存 ≠ 部署**。设计器保存只写模型，必须在列表页点「部署」才会进引擎、才会产生可发起的流程定义。这是控制台最容易被误解的一处。

设计器自己也有「部署」按钮，但它走的是 `POST /api/designer/deploy`：**不写 publish 快照、也不更新模型列表里的发布状态**。所以从设计器部署完，列表可能仍显示 `未发布` / `未发布修改`。两个入口的差别：

| 入口 | 端点 | 预检 | 写版本快照（历史里能看到流程图） | 更新列表发布状态 |
| --- | --- | --- | --- | --- |
| 列表页「部署」 | `POST /api/admin/models/{id}/publish` | 有（阻断级直接拦） | 有 | 有 |
| 设计器内「部署」 | `POST /api/designer/deploy` | 本地镜像规则 | 无 | 无 |

**统一走列表页「部署」**，除非你只是想把 XML 快速推给引擎试一下。

### 2.4 校验与部署（核心动作）

点行内「部署」→ 确认弹窗：

> 标题 `部署流程模型「xxx」？`
> 内容 `将按标准版 BPMN 规则校验流程图，通过后部署到引擎并递增版本；同时把当前流程图写入版本历史。`
> 按钮 `部署` / `取消`

确认后是**三段式**：

1. **预检**（`POST /api/admin/models/{id}/validate`）：有阻断级问题时弹 `发布被拦截：N 处阻断问题`，每条显示 `规则名` + 说明，**不会部署**。
2. **渲染快照 + 部署**：先取详情渲染流程图 SVG，再调 `publish`（带 `Idempotency-Key`），后端解析 + 校验 + 版本递增，并把 XML 与图片写入 `publish` 版本快照。
3. **结果**：
   - 内容没变 → **跳过部署**，提示 `内容未变化，已跳过部署：key v3`（不会白刷版本号）；
   - 有提示级问题 → 弹窗 `已部署：key v3（2 条提示）`，副文案 `部署已成功。以下问题不影响定义落库，但实例运行到相关节点时可能失败，建议先修正再发起实例。`；
   - 干净通过 → `已部署：key v3`。

> 部署失败的提示前缀是 `部署失败：`，常见原因：排他网关缺默认流、服务任务的 topic 与 class 混写、表达式语法错。

### 2.5 其余行操作

| 按钮 | 行为 | 是否需要确认 |
| --- | --- | --- |
| `编辑` | 进内嵌设计器 | 否 |
| `部署` | 见 §2.4 | 是 |
| `导出` | 下载 `${processKey}.bpmn20.xml` | 否 |
| 复制图标（悬停 `复制模型（副本从版本 1 开始）`） | 复制一份模型 | 否 |
| `历史` | 打开版本历史抽屉 | 否 |
| 删除图标 | `删除流程模型「xxx」？` / `删除后不可恢复（不影响已部署的定义）。` | 是 |

### 2.6 版本历史抽屉

标题 `版本历史 · 模型名`。

顶部一行：`保留最近 [10] 个版本，清理更早的快照` + 右侧 `清理旧版本`（危险按钮，Popconfirm 标题 `确认清理旧版本？`，说明 `将删除较早的快照、只保留最近 N 版（最新版本永远保留），不可恢复。`）。

表格列：`版本`（v1/v2…）、`动作`、`流程名称`、`操作人`、`时间`、`操作`。

`动作` 列的标签含义：

| 标签 | 来源 |
| --- | --- |
| `保存` | 设计器保存 |
| `部署` | 发布时写入的快照；若该快照对应线上版本，追加青色 `线上 vN` |
| `回滚` | 从旧版本回滚产生的新版本 |

行操作：
- `流程图` → 打开 `流程图 · v3 名称` 弹窗，优先显示部署快照的 SVG，否则用设计器渲染 XML；
- `回滚` → Popconfirm `回滚到 v2？` / `该版本内容将作为新版本写入，历史保留。` → 成功 `已回滚到版本 v2（写入为最新版本）`。

> 回滚**不会自动部署**，仍需回列表点「部署」。

## 3. 部署管理（`/deployments`）

这里看的是**引擎里的流程定义**（部署产物），不是模型。

### 3.1 列表与搜索

- 搜索框 `搜索部署名 / 部署 ID / 流程 Key`（清空即撤销过滤）；
- 计数 `共 N 次部署` / `匹配 N 次部署（共 M 次）`，有折叠时追加 `· 已折叠 N 次历史部署`；
- 开关 `显示历史部署（N）`（默认关，见下方说明）；
- `刷新`。

表格列：`部署`（名称 + `N 个定义`，可复制部署 ID；有挂起定义时显示橙色 `挂起 N`）、`流程 Key`（最多 2 个 Tag，超出 `+N`）、`部署时间`、`最新版本`（`v3`）、`租户`（有租户时才出现）、`操作`。

> 📌 **发布新版本不会覆盖旧部署。** 引擎每发布一次就新建一次部署（`ACT_RE_DEPLOYMENT`），
> 所以同一流程发两版就会出现两条部署记录，看起来像"旧版本没并进历史版本"。
> 列表默认只显示**每个流程的最新那次部署**，被取代的收进页头开关 `显示历史部署（N）`；
> 旧版本本身没丢：展开当前部署 → `查看历史版本` 仍按 key 列出全部版本（含各自部署时间与状态）。
> 折叠只影响展示，删除部署 / 资源清单仍按部署实体走。

行操作两个图标：
- `查看资源清单`（文件夹图标）→ 弹窗列出 `资源名` / `流程定义 ID`；
- `删除部署`（红色垃圾桶）→ Popconfirm `删除部署「xxx」？` / `将级联删除其运行中的流程实例（历史保留）。` → 成功 `已删除部署：xxx`。

> ⚠️ 删除部署会**级联删掉运行中的实例**，只留历史。生产操作前先确认没有在途单据。

### 3.2 展开行的 6 个动作

点行首展开箭头，看到该部署包含的每个流程定义：`版本`、`流程 Key`、`名称`、`资源名`、`状态`（`运行中` / `已挂起`）、`操作`。

| 操作 | 说明 |
| --- | --- |
| `发起` | 打开发起弹窗；定义已挂起时按钮置灰，提示 `已挂起的流程定义不能发起实例，请先激活` |
| 另存为设计器模型（复制图标） | 把线上定义反建成模型，提示 `已从定义创建模型，正在打开设计器`，自动跳设计器 |
| 挂起 / 激活（暂停/播放图标） | 定义级挂起；挂起会**级联到运行实例**（`suspendProcessInstances=true`） |
| `查看历史版本` | 弹窗 `「key」的历史版本`，列出所有版本的状态与部署时间 |
| `查看 BPMN XML` | 弹窗展示 XML（等宽字体、可滚动），底部可 `下载 BPMN` |
| 下载图标 | 直接下载 `key-v3.bpmn20.xml` |

### 3.3 发起实例弹窗

标题 `发起实例：leave_process v3`，按钮 `发起` / `取消`。顶部蓝条：`按流程定义 xxx 发起（精确到该版本，不随新版本漂移）。`

| 字段 | 说明 |
| --- | --- |
| 业务主键（可选） | 占位 `如 ORDER-20261021-001` |
| 发起人（可选） | 占位 `如 zhangsan`；说明 `留空则使用当前登录身份；JWT 模式下填写值必须与令牌 sub 一致，否则 403。` |
| 初始变量（JSON 对象，可留空） | 占位 `{ "amount": 1200, "applicant": "zhangsan" }`；不是 JSON 对象时提示 `变量必须是 JSON 对象` |

成功后弹窗：标题 `已发起：key v3`，内容 `流程实例 ID：` + 可复制代码块，按钮 `查看实例详情`（跳 `/monitoring?instanceId=...`）。

> 这里是**引擎面**发起（`POST /api/runtime/process-instances`），不做平台面的参数 schema 校验。要走必填 / 可写性校验请用 `/workflow/v1/instances`。

### 3.4 挂起与删除的区别

| | 作用对象 | 影响 | 可恢复 |
| --- | --- | --- | --- |
| 定义级「挂起」 | 某个版本的**流程定义** | 不能再发起；`suspendProcessInstances=true` 时运行实例也一起挂起 | 点「激活」恢复 |
| 实例级「挂起」 | **单个实例** | 只影响这一单 | 点「激活」恢复 |
| 「删除部署」 | 整个部署 | 定义 + 运行实例全删，历史保留 | 不可恢复 |

## 4. 实例监控（`/monitoring`）

页面顶部一句话：`运行实例、待办任务与历史实例的实时监控；支持实例挂起/激活/跳转、任务认领/转办/完成。`
右上：`自动刷新（30s）` 开关 + `刷新`。

### 4.1 统计卡

`待办总数`、`已逾期`（>0 时数字变红）、`今日到期`、`按流程分布`（每个 key 一个 Tag + 数量，无数据时 `无待办`）。

### 4.2 四个页签

标签自带计数：`运行实例（N）`、`待办任务（N）`、`历史实例（N）`、`定时作业（N）`。

每个页签都有统一的条件栏：`查询`（primary）、`重置`（无生效条件时置灰）、生效时右侧出现 `已按条件筛选`。所有输入框回车即查询、支持清空。

### 4.3 运行实例

筛选：`流程 Key`、`业务主键`、`发起人`。

勾选后可批量：`批量挂起（N）`、`批量激活`、`批量迁移版本（N）`、`批量删除选中（N）`（危险，**无二次确认**）。

表格列：`流程 Key`、`业务主键`、`实例名称`、`发起人`、`开始时间`、`状态`（`运行中` / `已挂起`）、`操作`。

行操作：
- `详情` → 打开实例详情抽屉（§4.7）；
- `激活` / `挂起` → 直接生效，提示 `已激活实例` / `已挂起实例`；
- 删除图标 → Popconfirm `删除实例「xxx」？`，删除原因固定记为 `管理端删除`。

批量结果统一形如 `批量删除完成：成功 3 条，失败 1 条`。

**批量迁移版本**（危险操作）：弹窗顶部黄条 `迁移不可逆`，说明 `目标定义必须是同一个流程 key 的另一个版本；不同 key 的实例会失败并计入失败条数（逐项执行，不做整体回滚）。多实例节点不支持迁移，同样逐项失败。`
需要填 `目标流程定义 id`（占位 `demo:2:3f2a…`）和可选 `迁移原因（可选）`（`写进审计：为什么迁移、谁批准的`）。

### 4.4 待办任务

筛选：`办理人`、`候选人`、`流程实例 ID`、`节点 Key（可选）`（悬停说明：`节点 Key 需配合办理人 / 候选人 / 实例 ID 使用：后端要求至少给出其中一个身份或实例条件。`）。

勾选后可批量：`批量改到期时间（N）`、`批量转办（N）`。

表格列：`任务名`、`流程 Key`、`办理人`（空显示 `（未认领）`）、`优先级`、`创建时间`、`到期时间`、`操作`。

行操作：

| 操作 | 行为 | 提示 |
| --- | --- | --- |
| `认领` | 把任务签收给自己 | `已认领任务` |
| `取消认领` | 退回候选池 | `已取消认领` |
| 铅笔图标（`修改到期时间 / 优先级`） | 弹窗：`到期时间`、`优先级（0-100）` | `任务已更新` |
| `转办` | 弹窗 `转办任务「xxx」`，字段 `新办理人（留空表示退回未分配）` | `已转办` |
| `完成` | 弹窗 `完成任务「xxx」`，字段 `随完成写入的变量（JSON 对象，可留空）` | `已完成任务` |

> 「完成」是**引擎面直通**（`POST /api/runtime/tasks/{id}/complete`），不写审批语义、不校验 optionId。正式审批请用平台面 `/workflow/v1/tasks/{id}/submit`，控制台定位是「管理与运维」。

### 4.5 历史实例

筛选：`流程 Key`、`业务主键`、`发起人`、`状态`（`未结束` / `已结束` / `已删除`）。

状态列：`运行中`（蓝）/ `已结束` / `已删除`（红）。行操作只有 `详情`，打开**只读**抽屉。

### 4.6 定时作业

用于看「谁在等超时」。若接口 404 会显示黄条 `该管理接口返回 404：控制台可能指向了 Rest 宿主（默认 5080），也可能 Admin 宿主运行的是旧构建（需重新编译并重启）。`

筛选：`流程实例 ID`、`流程定义 ID`、到期时间（`只看该时刻之前到期的作业`）。
统计行：`共 N 条 · 已到期 N 条 · 1 小时内 N 条 · 最近到期 2026/11/3 10:00:00`。

列：`到期时间`、`流程实例`、`节点`、`边界事件`、`创建时间`、`操作`。
行操作：`改期`（弹窗 `作业改期（实例 / 边界事件）`）、`立即触发`（`已触发定时作业`）。

### 4.7 实例详情抽屉

标题：运行实例 `实例详情 · key`，历史 `历史实例 · key`。

头部信息（运行态）：`流程 Key`、`实例 ID`、`定义 ID`、`业务主键`、`实例名`、`发起人`、`开始时间`、`状态`、`租户`。
历史态额外有 `结束时间`、`耗时`、`删除原因`，并带标签 `历史实例（只读）`。

四个页签：

| 页签 | 内容 |
| --- | --- |
| `流程图` | 渲染 BPMN，当前节点高亮；无数据时 `暂无流程图数据（历史可能未启用）` |
| `变量（N）` / `历史变量（N）` | 运行态看 `变量名 / 值`；历史态还有 `类型`、`最后更新` |
| `活动时间线（N）` | 按时间正序，当前活动带 `当前` 标签，附 `开始 → 结束 · 办理人` |
| `历史任务（N）` | `任务名 / 办理人 / 开始 / 结束 / 删除原因` |

### 4.8 管理干预（仅运行实例）

按钮从左到右：`挂起`（或 `激活`）、`跳转节点`、`变量直写`、`迁移定义`、`删除实例`。

| 动作 | 弹窗 / 确认 | 后果 |
| --- | --- | --- |
| `挂起` / `激活` | 无确认 | 只影响本实例 |
| `跳转节点` | 字段 `目标节点 ID`（占位 `BPMN 元素 id（可填结束事件 id 强制办结）`）、`跳转原因（可选）`（`写入被删任务与活动历史`） | 当前待办作废，流程从目标节点继续 |
| `变量直写` | 黄条 `合并写入当前运行实例的流程变量，属于管理端高危操作（会写审计）。` + `变量（JSON 对象）`（预填当前全部变量，可直接改） | **合并**写入；空对象提示 `至少提供一个变量`；成功 `已写入 N 个变量` |
| `迁移定义` | 黄条 `迁移不可逆：目标定义的活动需与新版本对齐，待办会按映射重建。建议先勾选「仅预演」核对计划。` + `目标流程定义`（下拉带版本与挂起标记）、`迁移原因（可选）`、勾选框 **`仅预演（只算迁移计划，不落库）`（默认勾选）** | 预演成功 `迁移预演通过（未落库），确认无误后取消勾选再执行`；实跑成功 `迁移完成` |
| `删除实例` | Popconfirm `删除该实例？` / `待办 / 变量将被清理，历史保留。` | 删完自动关闭抽屉 |

> 迁移弹窗默认停在「仅预演」是刻意设计：先看计划再执行，避免直接把在途单据迁坏。

**活动实例（modify）** 分区：用自动补全输入 `活动 id（可从当前节点里选，也可手填）`，两个动作：
- `取消活动` → `已取消活动 xxx`；
- `在活动前启动` → `已在 xxx 之前启动新分支`。

底部说明：`取消：结束该活动的待办 / 定时作业并收口历史；在活动前启动：额外开一条分支，目标活动会重新执行。`

### 4.9 任务详情抽屉

从待办列表点「详情」打开，标题固定 `任务详情`。

信息区 19 项，重点：`办理人`（空显示 `未认领`）、`所有者`、`优先级`、`委派状态`、`认领时间`、`挂起状态`（`正常` / `已挂起`）、`流程实例`（可点，跳到实例详情）。

**任务操作**（一个输入框 + 四个按钮）：

| 按钮 | 前置条件 | 提示 |
| --- | --- | --- |
| `委派` | 填了用户/组 id | `已委派（解决后回到原办理人）` |
| `解决委派` | 委派状态为 PENDING | `已解决委派` |
| `加候选用户` | 填了 id | `已加候选用户` |
| `加候选组` | 填了 id 且组存在 | `已加候选组「组名」`；组不存在时 `组 'xxx' 不存在：请先在身份模块建组，再加为候选组` |

下方还有：`表单元数据（N 个属性）`、`身份关系（N）`（候选关系行可以「移除」，办理人/所有者行没有移除按钮）、`任务局部变量（N）`。

> 控制台**不提供「提交审批」**：TaskDetailDrawer 里没有 submit，审批走 `/workflow/v1/tasks/{id}/submit`。控制台的「完成」只是引擎层完成，不带审批选项与意见。

## 5. 外部任务（`/external-tasks`）

对应 BPMN 里的 `activiti:topic` 节点。顶部蓝条：`外部任务：activiti:topic 节点由 worker 拉取执行，引擎只登记任务、原地等回执`，并给出 `待领取 N 条 / 已锁定 N 条 / 死信 N 条（本屏共 N 条）；失败回执不会推进流程，死信需要人工处理。`

### 5.1 四种状态

| 状态 | 含义 |
| --- | --- |
| `待领取` | 已登记，等 worker 拉取 |
| `已锁定` | 某个 worker 领走了（`锁` 列显示 workerId 与到期时间） |
| `已完成` | worker 回执成功，流程已推进 |
| `死信` | 连续失败耗尽重试，**流程停在原地** |

### 5.2 筛选

`按 topic 过滤（与 BPMN 的 activiti:topic 逐字一致）`、状态下拉（`待领取`/`已锁定`/`已完成`/`死信`）、`按流程实例 ID 过滤`、`刷新`。

列表最多显示 200 条，达到上限会有黄条 `只显示了最近 200 条（服务端上限）`，并提示 `还没领走的任务越积越多，通常意味着某个 topic 没有 worker 在跑。`

### 5.3 三个动作

| 动作 | 出现条件 | 确认文案 | 提示 |
| --- | --- | --- | --- |
| 变量快照（文档图标） | 全部 | 无 | 弹窗 `topic · 变量快照`，展示登记那一刻的变量 |
| `重投` | 仅 `死信` | `重投这条死信？` / `节点仍停在原地；重投只是让它重新可被领取，剩余次数不填则用服务端默认值。` | `已重投：任务回到待领取，等 worker 重新领走并回执` |
| `解锁` | 仅 `已锁定` 且有 workerId | `释放 worker「xxx」的锁？` / `任务立刻回到待领取，不扣重试次数；worker 若还在处理，会出现重复执行（业务需幂等）。` | `已释放锁：任务回到待领取（重试次数没动）` |

> **为什么没有「领取」按钮**：领取与回执是 worker 的职责，控制台代劳会抢走 worker 的锁。控制台只做「看 + 干预」。
> **为什么「重投」不是普通 worker 权限**：它需要 `workflow:admin:instance`，避免 worker 凭据自己复活自己、把退避机制架空。

## 6. 接入管理（`/access`）

顶部蓝条：`接入管理走平台面 /admin/v1`，说明 `这里注册的每个接入系统都有独立 scope、流程白名单与配额；密钥只在创建 / 轮换时出现一次。旧路径 /api/admin/clients 仅保留兼容。`

两个页签：`接入系统（N）`、`租户（N）`。

### 6.1 租户

说明：`租户是配额与数据隔离的边界；停用是整租户止血开关（数据不动，可恢复）。`

列：`租户 id`、`名称`、`默认配额（次/分）`、`状态`（开关：`启用` / `停用`）、`创建时间`。
停用悬停提示 `停用会让其下全部客户端立即鉴权失败（数据不动）`。

`登记租户` 表单：`租户 id`（`字母 / 数字 / 下划线 / 短横线，1–64 位；已存在的租户不会被覆盖。`）、`名称`、`默认配额（次/分）`（默认 600）。
成功提示 `租户已登记（已存在的租户不会被覆盖）` —— 因为是幂等 PUT，重复提交不会覆盖已有配置。

### 6.2 接入系统

说明：`一系统一客户端：配额与审计按客户端记账。`

列：`接入系统`（名称 + clientId）、`租户`、`scope`（橙色=高危）、`可用流程`（空=`全部授权`）、`配额（次/分）`、`状态`（`使用中` / `已暂停` / `待启用` / `已注销`）、`密钥有效期`（空=`长期`）、`操作`。

`注册接入系统` 表单：

| 字段 | 说明 |
| --- | --- |
| `接入系统名称` | 必填，占位 `如 OA 门户 / 招聘系统` |
| `所属租户` | 默认 `default`；`绑定租户后只能访问该租户的数据` |
| `授权 scope` | 多选，必填；`橙色为高危项（需显式确认，服务端会二次校验）。` 选中高危时弹黄条 `包含高危 scope` |
| `可用流程 key` | 可多个；`留空 = 授权全部流程；白名单是中台隔离的核心手段。` |
| `配额（次/分）` / `密钥有效期（天）` | 默认 600 / 90 |

常见的 scope 选择：

| 场景 | 建议 scope |
| --- | --- |
| 只读流程目录 | `workflow:process:read` |
| 发起 + 查自己的单 | `workflow:instance:start`、`workflow:instance:read`、`workflow:task:read` |
| 审批 | 再加 `workflow:task:submit`、`workflow:history:read` |
| 外部任务 worker | `workflow:external:task` |
| 运维干预 | `workflow:admin:instance`（高危，读不到白给） |

> 不要把 `workflow:admin:instance` 发给普通业务系统：它能跳转节点、迁移实例、重投死信。

### 6.3 签发 / 轮换密钥（只出现一次）

注册成功**不弹 message**，直接弹出 `请立刻保存密钥`：

> 黄条 `明文密钥只出现这一次`
> 说明 `关闭后服务端只保留摘要，无法再次查看；丢了只能轮换（旧密钥有宽限期，不会立刻打断对接）。`
> 明文串可一键 `复制密钥`；底部显示 `客户端：xxx · 有效期至：… · 旧密钥宽限至：…`

关闭后想再看只能点行内 `轮换`（悬停 `换一把密钥（旧密钥有宽限期）`）。
按下 `我已保存` 是不可逆的：服务端只留摘要。

### 6.4 暂停与注销

- `暂停` / `启用`：Popconfirm `暂停该接入系统？`，提示 `已暂停「xxx」`；
- `注销`：Popconfirm `注销「xxx」？` / `密钥立即吊销；记录保留用于审计回查。`，不可恢复。

## 7. 审批字典（`/semantics`）

顶部蓝条：`审批语义字典：把流程私有的 optionId 翻译成平台稳定的语义`，说明 `调用方只认 semantic 与 outcomeClass，流程新增「转财务复核」这类选项不会破坏集成代码。字典按「租户 + 流程」生效；环节级映射优先于流程级默认。`

### 7.1 使用顺序（关键）

1. 在搜索框输流程 key（占位 `流程 key，如 leave_process`）→ 点 `加载`；
2. 右侧显示 `当前生效定义 v3 · 5 个环节声明了选项`；
3. 上半区 `定义里声明的选项（点「配置」直接补语义）`：每个环节一个蓝色 Tag，下面挂该环节声明的选项；**未配置的选项点一下就能预填**；
4. 配置完成，表格里出现映射行，选项 Tag 后面会多一个 `✓`。

> 左边那份清单来自**流程定义本身**（唯一真源），不是手填。没有它，运维只能翻 BPMN 猜 optionId。

### 7.2 语义与统计口径

| 语义 | 中文 | 统计口径（自动推导，不手填） |
| --- | --- | --- |
| `APPROVE` | 同意 / 通过 | 正向（计入通过率） |
| `REJECT` | 不同意 / 拒绝 | 负向（计入驳回 / 退回率） |
| `RETURN` | 退回重办 | 负向 |
| `DELEGATE` | 转办 / 移交 | 中性（不计入分子分母） |
| `CUSTOM` | 流程自定义 | 中性 |
| `SETTLED` | 办结（无审批结论） | 中性 |

> `outcomeClass` **不接受请求体**，由 `semantic` 推导。表单里也没有这个字段，只有说明文字 `统计口径（正向 / 负向 / 中性）由语义自动推导，不需要单独选。`

### 7.3 新增 / 编辑映射

表单字段：`选项 id（BPMN 里的 activiti:value/@id）`（可从声明里选，也可手填；**编辑时不可改**）、`作用范围`（留空=流程级默认，选环节=只对该环节生效，优先级更高）、`语义`、`显示名（可选）`、`必填审批意见`、`必选目标环节`、`允许退回 / 跳转的目标环节（可选）`。

保存提示 `已保存映射（下一条审批立刻按新语义解释）`；删除提示 `已删除映射（该选项回到「流程自定义」语义）`。

### 7.4 为什么"配了不生效"

| 现象 | 原因 |
| --- | --- |
| 手填了一个定义里不存在的 optionId | 不报错，但那行**永远不会生效**（运行时按定义声明去匹配） |
| 环节级配了但流程级也配了 | 环节级优先；确认你改的是哪一行（`作用范围` 列） |
| 流程没部署 / key 拼错 | 上半区读取失败提示 `读取流程定义里声明的选项失败：…（流程未部署 / key 拼错时就是这样；字典仍可手工维护）` |
| 换了租户 | 字典跟着当前管理身份所属租户走，**不接受请求体里的 tenantId** |

## 8. 事件订阅（`/subscriptions`）

顶部蓝条：`事件订阅：审批事件通过 outbox 投递到业务系统`，描述动态显示积压：`待发布 3 条 / 死信 1 条；最老一条待发布事件产生于 2026/11/3 10:00:00（看年龄而不是条数）`。

两个页签：`订阅（N）`、`死信（N）`。

### 8.1 订阅

说明：`订阅是配置数据：暂停会停止投递新事件，但已产生的事件仍按重试策略投递。`

列：`订阅`（名称 + `id · tenantId`）、`回调地址`、`事件类型`（空=`全部`）、`限速 / 重试`（`不限速` 或 `600/分` + `· 5 次`）、`密钥`（摘要，不可反推）、`状态`（开关：`启用` / `暂停`）、`操作`。

`新建事件订阅` 表单：`订阅名`、`回调地址`（必须 `http(s)://`）、`租户`（留空取默认）、`最大重试次数`（默认 5）、`每分钟上限`（`0 = 不限速`）、`事件类型白名单`（留空=全部）、`只关心某个流程定义（可选）`、`创建后立即启用`。

创建成功弹出 `请立刻保存订阅密钥`（同样只显示一次），说明 `关闭后只保留摘要；丢了就调「轮换」重新签发（对端要同步改，旧密钥立即失效）。`

行操作：
- `投递记录`（见 §8.2）；
- `轮换`：Popconfirm `轮换密钥？` / `旧密钥立即失效，对端要同步改；未消费的事件不受影响。`；
- 删除：`删除「xxx」？` / `删除后不再产生新投递；已产生的投递记录保留。`

启停提示：`已启用「xxx」` / `已暂停「xxx」（不再投递新事件）`。

### 8.2 投递记录

弹窗标题 `投递记录：订阅名`，顶部显示 `回调地址`、`限速`。表格：`事件`、`状态`、`次数`、`下次重试`、`最近错误`、`更新时间`、`操作`。

状态是**英文枚举**：`PENDING`（蓝）/ `DELIVERED`（绿）/ `FAILED`（黄）/ `DEAD_LETTER`（红）。只有 `DEAD_LETTER` 行才有重投按钮。

> 想验证回调地址是否通，只能靠真实业务事件驱动后看这里的状态与 `最近错误`，控制台**没有「测试投递」**。

### 8.3 死信

说明：`死信是一条也投不出去的事件：先修对端再重投，否则只是把失败次数再加一次。`

列：`事件`、`订阅`（订阅被删时显示 id + `配置已删`）、`次数`、`最近错误`、`入死信时间`、`操作`。
`重投` → Popconfirm `重新投递这条死信？` → `已重新投递：投递计数会继续累加，超过上限会再次进死信`。

> 如果原来订阅已被删除，重投前先重建订阅，否则事件没有收件人。

## 10. 审计日志（`/audit`）

标题 `管理动作审计`。右侧按钮：`刷新`、`导出 CSV`、`清理历史`。

说明文字：`记录转办、改任务 / 候选、跳转 / 迁移、实例挂起与删除、变量直写、部署与定义变更、归档与审计清理。被 403 拒绝的请求不会记录；明细只含变量名，不含变量值。`

### 10.1 筛选

`操作人`、`动作`、`实例 id`、`结果`（`全部`/`成功`/`失败`）、`时间`（可只填一端）、`查询`、`重置`。

`动作` 是自动补全，可手填，常用值：`task.reassign`、`task.candidate_add`、`instance.jump`、`instance.migrate`、`instance.delete`、`variable.write`、`deployment.create`、`model.publish`、`audit.purge` 等。

### 10.2 列表

列：`时间`、`操作人`（附鉴权方式 Tag）、`动作`（配色：删除/清理红、变量紫、部署蓝、实例橙）、`目标`（`类型: id`）、`实例`、`结果`（`成功`/`失败`，悬停看错误）。

有明细或错误的行可展开，看到 `明细`（格式化 JSON）与 `错误`。

### 10.3 导出与清理

- `导出 CSV`：按当前筛选条件导出，文件名 `audit-<时间戳>.csv`，成功 `已导出当前筛选条件下的审计记录`。
- `清理历史`：弹窗 `清理审计记录`，正文 `删除该时刻之前的全部审计记录（当前租户），不可恢复。清理动作本身会留下一条 audit.purge 记录。` 默认时间 30 天前，成功 `已清理 N 条（早于 …）`。

> 清理动作本身也被审计，所以"抹掉痕迹"这件事会留痕。

## 11. 管理指标（`/metrics`）

标题 `管理指标`。右上：窗口下拉 `最近 1 天 / 最近 7 天 / 最近 30 天 / 最近 90 天`（默认 7 天）、`审计窗口`、生成时间、`刷新`。

说明：`租户口径 [标签] 「不可用」表示当前宿主无法统计（如内存宿主没有任务表、归档未启用），不是 0。`

九个指标卡：`运行中实例`、`待办总数`、`逾期待办`（>0 变红并带 ⚠）、`今日到期`、`历史实例`、`已结束`、`已删除`、`流程定义`、`已归档实例`。

值为 `不可用` 时表示宿主无法统计，悬停 `?` 看原因（如 `内存宿主没有任务表，无法统计`）。

下面两张卡片：
- `待办分布（按流程 key）`：`流程 key`、`待办数`、`占比`（进度条）；空时 `当前没有待办`；
- `审计动作（N 天窗口）`：动作 Tag + 次数；空时 `窗口内没有管理动作`。

> 「今日到期」按浏览器时区换算自然日（请求里带 `timeZoneOffsetMinutes`）。

## 12. Redis 诊断（`/redis`）

标题 `Redis 作业队列`，每 10 秒自动刷新。

### 12.1 三种状态必须分清

| 颜色 | 标题 | 含义 | 该做什么 |
| --- | --- | --- | --- |
| 红 | `Redis 诊断接口不可用` | **查不出来**（接口失败），不代表没配 | 确认登录态、宿主在跑（`/health/ready`），再刷新 |
| 黄 | `当前宿主的作业队列不是 Redis` | 确实用进程内队列，Redis 里不会有任何 netbpm 键 | 要 Redis 就配 `NetBpm:Jobs:Queue:Provider = Redis` |
| 红 | `Redis 连接不可用` | 配了但 PING 不通 | 查 Redis 是否启动、Host/Port/Auth/Database、网络与防火墙 |

第二种状态下的原文：`作业队列走进程内优先队列，Redis 里不会出现任何 netbpm 键。`
第三种状态下会说明后果：`异步作业仍会由数据库兜底扫库执行，但「到期即时唤醒」与「多宿主共享队列」已失效。`

### 12.2 信息区

`队列实现`、`目标地址`、`逻辑库`、`键前缀`、`TLS`、`连接来源`（`ConnectionString（Host / Port / Database 配置被忽略）` 或 `Host / Port / Database 配置项`）、`连接状态`（`PING 成功` / `连接不可用` / `未使用 Redis`）、`PING 时延`。

四个统计卡：`队列提示总数`、`延迟段`、`就绪段`、`在途段`。

### 12.3 队列键

三个键：`delay`（延迟段，zset）、`ready`（就绪段，list）、`inflight`（在途段，zset）。

> 说明文字：`三个键都没有数据是正常的：Redis 只存「作业到期提示」，作业执行完即从 inflight 移除，空键由 Redis 自动回收；流程实例、任务、历史等数据始终在数据库里。`

### 12.4 服务端信息

`版本`、`运行模式`、`已运行`、`连接数`、`已用内存`、`累计命令`、`命中次数`、`未命中次数`、`命中率`，以及各逻辑库键数量（当前库高亮）。

> 口令永远不回传；连接串只以 `usesConnectionString` 布尔标记体现。

## 13. 流程类型（`/process-types`）

业务侧的「流程名片」：给每个流程 key 配名称、描述、查看页 / 审批页地址、排序与启停。

工具栏：搜索框 `搜索名称 / 描述 / 页面地址`（纯前端过滤）、说明文字（`拖动行可调整顺序，保存后按 sort_order 生效`，搜索时变成 `匹配 N / M 个流程类型（搜索时不可拖拽）`）、`新建流程类型`。

列：拖拽把手、`流程名称`、`描述`、`查看页 / 审批页`、`排序`、`状态`（`启用` / `停用`）、`操作`。

**拖拽排序**：按住行首把手拖动，松手即逐条保存，提示 `排序已保存`；失败 `保存排序失败：…` 并回滚。搜索状态下禁止拖拽（避免只重排过滤结果）。

表单字段：`流程名称（= 流程 key）`、`描述`、`业务单查看页地址（支持 {businessId}/{processInstanceId} 占位符）`、`流程审批页地址（支持 {taskId}/{processInstanceId} 占位符）`、`排序（小在前）`、`是否启用`。

> 这里的 `流程名称` 前端标注为「= 流程 key」，后端**不做校验**、也不与流程定义建立外键。按约定填成 BPMN 的 `process id` 最省事——运维在审计、监控里看到的就是同一个字符串。

## 14. 权限与账号

### 14.1 两套 scope 口径（最容易踩的坑）

控制台同时挂在两套鉴权面上：

| 面 | 端点前缀 | scope 命名 | 用它的页面 |
| --- | --- | --- | --- |
| 引擎管理面（旧） | `/api/admin/**`、`/api/runtime/**`、`/api/designer/**` | `netbpm.admin`、`netbpm.admin.model.read`、`netbpm.admin.audit.read` … | 流程模型、流程类型、部署、实例监控、审计、指标、Redis |
| 平台管理面（新） | `/admin/v1/**` | `workflow:admin:client`、`workflow:admin:process`、`workflow:event:subscribe` … | 接入管理、审批字典、事件订阅、配额总览 |

好消息：`netbpm.admin` 是**万能钥匙**——服务端对 JWT 且持有 `netbpm.admin` 的请求，在平台面直接放行（代码里明确写了「引擎超管就是平台管理员」），并且两套名字之间还有互认映射（`netbpm.admin.audit.read` ↔ `workflow:admin:audit:read`）。

所以：**要么给 `netbpm.admin`，要么两套细粒度 scope 各给一份**。

### 14.2 页面 → scope 对照

| 页面 | 需要的 scope（二选一即可） |
| --- | --- |
| 流程模型 / 流程类型 | `netbpm.admin.model.read`（读）、`netbpm.admin.model.write`（写） |
| 部署管理 | 同上（`/api/designer/**` 与 `/api/admin/models/from-definition`） |
| 接入管理 / 配额总览 | `workflow:admin:client` |
| 审批字典 | `workflow:admin:process` |
| 事件订阅 | `workflow:event:subscribe` |
| 实例监控 | 管理读权限（`netbpm.admin` 最省事） |
| 外部任务 | 读 / 解锁 `workflow:external:task`；重投 `workflow:admin:instance` |
| 审计日志 | `netbpm.admin.audit.read`；清理另需 `netbpm.admin.audit.purge` |
| 管理指标 | `netbpm.admin.metrics.read` |
| Redis 诊断 | `netbpm.admin.redis.read` |

> `/admin/v1` 还有一道统一守卫：至少需要一个管理类 scope，否则 403 并提示「调用 /admin/v1 至少需要一个管理类 scope」。

### 14.3 账号维护

```bash
# 新建
dotnet run --project tools/NetBpm.DbMigrate -- users add --username alice --scopes netbpm.admin
# 改口令
dotnet run --project tools/NetBpm.DbMigrate -- users reset-password --username alice
# 查看账号列表与锁定状态（含失败次数）
dotnet run --project tools/NetBpm.DbMigrate -- users list
```

可用参数：`--display-name`、`--tenant`、`--scopes`（空格分隔多个）、`--password`（省略则交互输入）。
口令至少 8 位；连续失败 5 次会临时锁定。

## 15. 排错手册

| 现象 | 最可能的原因 | 处理 |
| --- | --- | --- |
| 整页 404 / 顶部红条 | 控制台指向了 5080（Rest 宿主） | 改用 5081；开发时设 `NETBPM_API_TARGET=http://localhost:5081` 并重启 Vite |
| 新功能页 404，老页正常 | Admin 是旧构建 | 重新编译并重启 `NetBpm.Admin` |
| 登录报 `jwt_not_configured` | 没配 `NetBpm:Security:Jwt:SigningKey` | 配密钥，或改用服务凭据登录 |
| 401 并跳登录 | 凭据过期 / 密钥被吊销 | 重新登录；客户端密钥被轮换的话拿新密钥 |
| 403「缺少授权范围」 | scope 不足 | 见 §14.2；偷懒就给 `netbpm.admin` |
| 403 `tenant.forbidden` | 跨租户写 | 跨租户读是 404、写是 403，属预期行为 |
| 部署被拦截 | BPMN 有阻断级问题 | 按弹窗里的规则名逐条改（网关默认流、topic 与 class 互斥等） |
| 发布新版本后旧部署还占一行 | 开关 `显示历史部署` 开着；或那次部署里还含同 Key 的当前版本定义 | 关掉开关；确属重复部署则删掉多余那条（级联注意在途实例） |
| 部署成功但实例跑不动 | 部署弹窗里有 `warnings` | 那些提示就是"哪个节点会失败"，先修再发起 |
| 「我的待办」看不到单子 | 用了 `assignee` 而非 `candidateUsers` | 见 `docs/approver-resolution-guide.md` §5.3 |
| 候选组任务谁都看不见 | `IUserGroupManager` 还是空实现 | 注册业务适配器；部署时会有 LogWarning |
| 外部任务堆积 | 没有 worker 在跑该 topic | 看 `待领取` 数量与 topic 拼写 |
| 事件一直进死信 | 对端不可用 / 签名不对 | 修对端，再在死信页「重投」 |
| Redis 页黄色 | 本来就没用 Redis | 正常；要共享队列才配 Provider=Redis |
| 清理历史后图看不到了 | 快照被清理 | 历史版本只保留最近 N 版，重要版本先别清 |

## 16. 约定与危险操作清单

**通用约定**

- 时间统一显示为 `2026/11/3 10:00:00`（`zh-CN`，24 小时制），空值显示 `—`。
- 列表默认每页 20 条；实例监控四个页签可改每页条数并显示 `共 N 条`。
- 搜索框大多"回车生效、清空撤销"，不是输入即查。
- 必填校验提示统一为 `请输入…` / `请选择…`。

**需要二次确认的只有 4 处**

1. 删除部署（`将级联删除其运行中的流程实例（历史保留）。`）
2. 删除实例（列表行 / 抽屉内两套文案）
3. 回滚版本（`该版本内容将作为新版本写入，历史保留。`）
4. 清理版本历史（`不可恢复`）

**没有二次确认但很危险的操作**：批量删除实例、批量挂起/激活、批量迁移、取消活动、立即触发作业、变量直写、注销接入系统、清理审计。**执行前自己确认选中范围**。

**不可逆操作**：删除部署、删除实例、清理审计、清理版本历史、注销客户端、关闭密钥弹窗。
