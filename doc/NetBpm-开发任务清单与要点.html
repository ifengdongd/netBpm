0.2 三个"贵资产"（砍范围换来的红利，别再丢掉）

  1. 沿用 ACT_* 表名与列名 → 库级行快照对拍能力。这是全项目最强的验证手段：能抓到 API 层看不出的执行树内部差异（标志位错、子执行多建/少建、Join 该删的没删）。
  2. Java 预言机就是免费的权威 Oracle → "判定正确的唯一客观标准 = 与 Activiti 输出一致"从口号变成可执行的 CI 门禁。
  3. NetBpm.Workflow 公共类 → 从"引擎"升维到"审批流产品"：宿主五步接入即获得发起 / 待办 / 审批 / 历史 / 流程图 / 改派 / 跳转全部能力，业务侧只实现 IBusinessProcess。

0.3 五个已踩过并固化的坑（最值钱的部分）

#坑一句话结论
1内存宿主与真库宿主行为分叉嵌套 fork/join 时 execution.Parent 在真库宿主为 null（只带 PARENT_ID_）→ 必须走异步 ResolveParentAsync；内存模式跑通 ≠ 正确
2宿主"启动时读配置"不可用测试覆盖ConfigureAppConfiguration 对注册阶段已读的配置无效 → 集成测试必须用 UseSetting，且必须断言"库里真的有了行"
3EL 语义与直觉大面积相反"1"+"2"==3、5/2==2.5、"abc"==1 抛异常、null<1 恒 false —— 照搬错了会直接走错分支
4Agenda 不能写成递归递归在并行 Join 场景下受"谁先到达"时序影响产生错误结果；必须队列 + 单命令内排空
5同一条历史语义被绑在两个端口上"收口历史行"与"离开事件"必须拆成两个 API（RecordActivityEndAsync / RecordActivityEndQuietlyAsync），否则并行 Join 事件序列全错

0.4 还剩什么

  • 必须补（业务高频）：脚本任务执行（Roslyn）、多实例会签。
  • 可以不做（有意出界）：子流程 / 调用活动、边界事件、定时器与消息事件、泳道、动态流程修改、表单引擎、图形 PNG 生成、其余 6 方言。
  • 工程硬化欠账：并发压测数据、崩溃恢复演练、可观测性（指标/追踪）、CI 流水线落地。

WP4 表达式语言（P3）★

#任务交付物要点
T4.1扫描器 + 递归下降Scanner.cs / ElParser.cs双模式（${} 与 #{} 不可混用）；字符串转义只允许 \\ 与转义引号 —— "\n" 是词法错误
T4.2AST 与求值Ast/* + ExpressionManager逻辑短路、三目惰性且右结合；整串先 trim 再解析（尾随空格会丢）
T4.3类型转换与比较TypeConverter / BooleanOperations / NumberOperations数值提升顺序照搬：BigDecimal → Float/Double → BigInteger → 整数 → String → Comparable；遇 null 的比较一律 false 不抛
T4.4解析器族ElResolver（变量作用域 / Map / List / Array / Bean）属性名 .NET 与 Java 大小写不同 → 先精确匹配再忽略大小写；length()/size()/contains()/substring(a,b) 必须做垫片
T4.5JUEL 对拍用例223 条（193 求值 + 30 响亮失败）每条期望值注明取自 JUEL 哪个分支，尤其把反直觉语义单独成组钉死

T4 的三条硬红线（写错必走错分支）

  1. + 从不拼字符串："1" + "2" = 3，"a" + 1 抛异常。
  2. / 恒为浮点除：5 / 2 = 2.5，除零得 Infinity/NaN 不抛。
  3. "abc" == 1 抛异常而不是 false（整数分支排在字符串分支之前）。

WP6 持久化层（P5）

#任务交付物要点
T6.1双方言 DDLdb/{mysql,sqlserver}/0001..0008引擎表恰好 13 张 ACT_*；0001 不得出现被裁掉的 12 张表名（有测试守着）；表注释：MySQL 内联、SQL Server 用 sp_addextendedproperty
T6.2ID 区块生成器DbIdGenerator从 ACT_GE_PROPERTY.next.dbid 一次占 2500、REV_ 乐观锁更新、进程内自增发放；改成 UUID/自增会让库级对拍全线失败
T6.3仓储族DapperExecutionManager / DapperTaskManager / DapperVariableInstanceManager / DapperHistoryManager / DapperProcessDefinitionStoreDapper 不做下划线→驼峰映射 → 所有手工 SQL 显式 as 别名；保留字要反引号；别用 select *
T6.4变量类型映射VariableTypeMapper列布局：string→TEXT_；整数→LONG_ 和 TEXT_；double→只 DOUBLE_；bool→只 LONG_；date→LONG_（UTC 毫秒）；null→TYPE_='null' 且值列全空。TEXT2_ 不是截断列，是 json 类型类全名辅助列。超 4000 字符串 / bytes / serializable 响亮失败，绝不截断
T6.5会话与事务DbSession / IDbSession / TransactionInterceptor一个命令 = 一个事务；历史行同事务内即时写（与 Activiti 的一级缓存 flush 等效，提交后可见结果一致）
T6.6迁移与校验工具NetBpm.DbMigrate（migrate / check / probe / purge）+ DatabaseMigrator / EngineTableCleaner无迁移记录表：靠"ACT_GE_PROPERTY 是否存在 + schema.version 匹配"判幂等 ⇒ 已初始化的库不会再跑脚本，改动必须手工 ALTER。清库顺序：身份关系先于任务（外键约束）

WP7 引擎运行时（P6）★★ 全部难点所在

#任务交付物要点
T7.1执行树实体ExecutionEntity / IExecutionEntity / IDelegateExecution根执行：IS_SCOPE_=1、PARENT_ID_=null、ACT_ID_ 恒 null、不参与推进；另有一个子执行走完全流程。把根执行放进推进路径会让并行 Join 的"删除其余非活跃执行"误删流程实例根执行
T7.2三标志位IsActive / IsConcurrent / IsScopeIS_CONCURRENT_ 在 Activiti 9 里永远不会被置 1（无调用点）—— 必须按"恒 false"实现，否则该列系统性差异。写"标志位不变量"断言（IsConcurrent ⇒ ParentId != null）
T7.3Agenda 与 4 OperationEngineAgenda + ContinueProcess / TakeOutgoingSequenceFlows / EndExecution / TriggerExecution绝不写成递归；一个命令一个事务、事务内排空 Agenda；循环里不 await 外部 IO。分支产生：第一条流出流复用当前执行，其余每条新建子执行，全部建完才统一推进。结束判定 = activeChildren == 0
T7.4网关行为排他 / 并行 / 包含排他：取第一个条件为真且非 default 的流，不加"多真报错"。并行：先 Inactivate() → 找同活动 id 的非活动执行 → 判定总数相等（不是"每条流入过"）→ 出口 evaluateConditions: false。包含：条件分叉 + 按入流数同步
T7.5任务行为用户任务全生命周期 / 服务任务 / 手工任务 / 脚本任务占位用户任务触发前置校验：执行上若还有未删任务 → 抛 UserTask should not be signalled before complete（错误文案也参与对拍）。候选值切分按 [\s]*,[\s]*，不是 Split(',')+Trim
T7.6变量作用域VariableInstance / IVariableScopesetVariable(x,v) 落在最上层变量作用域（本子集 = 流程实例根执行），否则并行兄弟分支互相看不见对方的变量；作用域首次访问一次查全再沿父上溯
T7.7命令 + 拦截器链6 命令 + Log / Transaction / CommandContext 拦截器CommandContext 用 AsyncLocal 而非 ThreadLocal；跨命令恢复等待型节点只带 ACT_ID_ 字符串 ⇒ 必须靠 IProcessDefinitionResolver 端口回解析元素
T7.8事件分发与监听器EngineEventDispatcher + ListenerInvoker + 执行/任务/事件监听器三选一实现（class / delegateExpression / expression）；throwOnFailure=true 才让监听器抛错失败，缺省只记警告；流程级执行监听器 = 全局观测，任何节点的 start/end 与任何流的 take 都通知
T7.9历史管理器IHistoryManager + 5 张历史表写入见下方「历史语义 8 条」

历史语义 8 条（对拍重灾区）

  1. 历史行 id = 运行行 id，只有 ACT_HI_ACTINST.ID_ 是新生成的。
  2. ACT_TYPE_ 取元素类名首字母小写，不是 getProperty("type")。
  3. 顺序流不产生活动行 —— 执行到流时收口的是源节点那一行。
  4. 历史身份关系只增不删：任务完成/实例结束后 ACT_HI_IDENTITYLINK 行保留。
  5. 历史变量行 REV_ 恒 0（DB 里的 1 是 INSERT 写死的；更新时 REV_ 不动）。
  6. 任务落库后回填 ACT_HI_ACTINST.TASK_ID_；变更办理人后回填 ASSIGNEE_，都发生在建行之后。
  7. "收口历史行"与"离开事件"必须拆成两个端口，并行网关每次到达只收口不发事件。
  8. 变量事件必须早于 PROCESS_STARTED；PROCESS_*/TASK_* 事件不填 activityId。

3. 横切要点精要（20 条，按主题）

3.1 执行树与调度

  1. 根执行不参与推进；一旦放进去，并行 Join 会误删流程实例。
  2. IS_CONCURRENT_ 恒 false（Activiti 9 事实，与计划原文相反）。
  3. Agenda 必须队列 + 排空，不能递归；一个命令一个事务，循环内不 await 外部 IO。
  4. 分支产生：第一条流出流复用当前执行，其余新建子执行；全部建完才统一推进。
  5. 实例结束判定 = 不存在 active 子执行（这就是"合并"的本质）。

3.2 网关语义

  1. 排他 = 取第一个为真且非 default 的流；不加多真报错。
  2. 并行 = 先置非活动 → 按入流条数总数相等判定 → 出口不校验条件。
  3. 排他/包含网关"全条件且无默认流"在 NetBpm 是部署期拒（Activiti 是运行期抛）。

3.3 表达式

  1. + 不拼串、/ 恒浮点除、"abc"==1 抛异常、null 比较恒 false —— 四条反直觉语义必须逐条对齐。
  2. 不用第三方表达式库：Flee / NCalc / DynamicExpresso 的隐式转换与 null 比较语义差异正好落在"流程分支出错的高发区"。

3.4 持久化

  1. ID 生成器必须区块分配（2500）+ REV_ 乐观锁，否则库级对拍全线失败。
  2. 变量列布局与类型映射要对齐到列（含 null 型、date 的 UTC 毫秒、TEXT2_ 的真实含义）。
  3. db 0001 只建 13 张表，且不得出现被裁掉的 12 张表名（测试守着，注释也会被剥离后检查）。
  4. 无迁移记录表：已初始化的库不会重跑脚本 → 现网变更必须手工 ALTER。

3.5 宿主与集成

  1. "启动时读配置"的宿主无法用 ConfigureAppConfiguration 覆盖 → 集成测试用 UseSetting，并断言"库里真有行"。
  2. 内存宿主 ≠ 真库宿主：Parent 懒加载、变量历史写入等差异只在真库暴露，内存模式跑通不代表正确。
  3. Dapper 不做下划线→驼峰映射：所有 SQL 显式别名，别用 select *。

3.6 应用层

  1. SubmitAsync 的落库顺序是契约（业务 → 参数 → 结论 → 实例登记 → 待办 → 流水）。
  2. 审批历史双源单出口：引擎侧权威，业务侧补意见；taskId 关联优先，退化按活动名按序认领。
  3. 服务任务委托只用一句：_workflow.CompleteAsync(execution, WorkflowOutcomes.Approved, ct)。

6. 若要"照这个模式再做一个"的最小任务集

  1. 冻结范围（书面签字）—— 12 条"不做"比 30 条"要做"更值钱。

  4. 先做表达式语言与执行树语义，再谈功能数量。前 90 天不追功能，打穿两个最大风险。
  5. 差异回写代码，不进台账；门禁（一致率 + 差异结论率）写进 CI。
  6. 语言/线程模型差异处（ThreadLocal → AsyncLocal）用分析器红线锁死，不靠自觉。
